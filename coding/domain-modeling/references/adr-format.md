# ADR 格式

沿用项目位置和编号。无约定时使用 `docs/adr/0001-<decision>.md`，扫描当前最高编号再递增；并行候选由主 agent 串行分配编号，避免冲突。

```markdown
# <决定名称>

<背景、真实决定和理由；通常一到三句话>
```

仅在增加实际信息时补状态、被拒绝的替代方案和非显然后果。重开决定时，新 ADR 说明替代对象，原 ADR 保留理由并链接新记录；沿用项目的 proposed/accepted/superseded 等 ADR 状态约定，不与 Change 的交付状态混用。

架构形态、数据所有权、跨模块交互、具有明显迁移成本的技术选择，以及代码看不出的限制可能值得记录。库选择、常规实现和暂时没时间不自动构成 ADR。

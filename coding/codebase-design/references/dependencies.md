# 依赖与测试

| 依赖性质 | 设计与验证策略 |
| --- | --- |
| 纯计算、进程内状态 | 优先真实实现，直接通过完整行为接口验证，不额外发明 adapter |
| 可本地替代的资源 | 使用适当测试资源或明确替代，核对语义差异；不为测试把内部细节全部公开 |
| 自有远程系统 | 业务逻辑位于明确模块，传输通过实际需要的接口/adapter；保留承诺的真实边界检查 |
| 第三方服务 | 注入外部操作接口，测试本方处理逻辑；必要外部交互单独验证 |

接口可以有内部替换位置，不需要全部成为调用者可见的外部接口。用测试 adapter 得到的逻辑结果，不能代替真实存储、协议或跨进程保证。

合并浅模块时通过新的行为接口建立验证，再评估旧测试是否真的冗余。只有确认原有独立行为仍被覆盖，且属于批准重构范围时才移除冗余测试；不因为出现了高层测试就自动删除全部单元测试。

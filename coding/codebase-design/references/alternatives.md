# 方案比较

只有重要接口或所有权问题存在多个合理方案时使用，不把每次设计都变成多方案竞赛。

先定义共同目标、约束、调用者和依赖，给出足以说明问题的小例子。默认主 agent 比较必要方案；用户明确请求多 agent 或适用指令授权后，才按当前 pi-subagents 指引委派有不同角度的只读设计任务。

各方案回答：接口及重要约束、调用例子、内部隐藏什么、依赖处理和真实取舍。可以分别从最小接口、常见调用者、必要灵活性等角度设计，不仅改名字或文件布局。

按调用者需要知道多少、变化是否集中、测试是否自然、兼容与迁移成本进行比较，给出有依据的推荐。子 agent 不改项目文件，不自行批准方案，主 agent 将重要选择交给用户；不要默认启动三个以上 agent，也不要自动写 ADR。

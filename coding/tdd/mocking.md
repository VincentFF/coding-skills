# Mock 与依赖替换

优先运行真实的进程内逻辑。不要为了证明内部某个方法被调用而 mock 自己的模块；测试应通过约定接口观察结果。

| 依赖 | 默认策略 | 证明范围 |
| --- | --- | --- |
| 纯计算、进程内状态 | 真实实现 | 接口行为及进程内状态转换 |
| 数据库或文件系统 | 合适的真实测试资源优先，必要时使用明确的本地替代 | 替代方案有语义差异时，不能证明真实资源的全部保证 |
| 自有远程系统 | 已有接口后注入 test adapter，并保留所需边界验证 | 内存 adapter 证明逻辑，不单独证明传输或跨进程性质 |
| 第三方服务 | 系统边界使用 mock/test adapter | 证明本方处理；第三方交互保证需要适当的契约或集成检查 |
| 时间和随机数 | 注入可控来源 | 确定性逻辑，不自动证明真实调度和竞态 |

在系统边界注入依赖，不由内部逻辑直接构造不可替换的客户端。接口围绕具体操作和返回形状，避免为测试发明大量条件分支的通用 fetcher。

替换策略跟随批准的验证范围，不降低范围来配合测试。只在真实变体或必要隔离存在时增加接口，不把每个内部对象都变成抽象。

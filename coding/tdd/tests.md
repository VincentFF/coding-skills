# 行为测试示例

## 同一个行为，不同的观察方式

| 目标 | 不合适的断言 | 合适的断言 |
| --- | --- | --- |
| 创建后可以查到用户 | 私有 repository 被调用一次 | 通过公开创建接口创建，再经公开查询接口读取所需字段 |
| 无权限时拒绝操作 | 内部授权函数返回 false | 从约定入口发起操作，检查契约规定的拒绝结果和副作用 |
| 两笔价格相加 | 用相同 reduce 算法算出预期值 | 使用独立已知实例：10 与 5 的总额为 15 |
| 重启后仍可读取数据 | in-memory fake 返回之前写入的值 | 在承诺的真实存储和进程边界上重启，再经公开接口读取 |

内部调用次数或顺序仅在它们本身就是批准的可观察契约时才作为断言。持久性目标不能用同进程缓存或 fake 的结果替代。

## 测试有效性

- 名称描述能力或失败场景，不描述内部步骤。
- 使用公开接口，保持内部结构变化时有效。
- 预期结果是独立的，不从当前输出或实现算法生成答案。
- 确认 runner 真正执行了测试，断言被等待且没有被吞掉。
- 控制时间、随机性和外部状态，区分症状与测试环境失败。
- 能说明哪种违反目标行为的缺陷会让测试失败。

先测试一个完整行为，再实现它，再进入下一行为。只验证「没有抛错」通常不足以证明要求中的结果和副作用。

# TDD

通过公开接口测试行为，一次完成一个 red → green 切片。按已有 Glossary 命名，尊重批准的行为和设计契约；本 skill 不启动其他 agent。

## 测试位置

使用批准计划中的测试接口，说明可捕获的错误和无法证明的范围。已有批准时不逐个测试重复询问；缺少影响契约的测试位置决定或需要改变接口时，先交主 agent。

当模块接口本身需要设计时，读取 [codebase-design](../codebase-design/SKILL.md) 提出方案；读取设计参考不授权改变已批准边界。契约空白、冲突与局部实现选择按 [文档契约](../change-planning/references/document-contract.md) 处理。

测试应在目标行为被破坏时失败，并在内部重构而行为不变时保持有效。预期值来自契约、已知实例或独立来源，不重复实现算法。写测试前阅读 [测试示例](tests.md)；需要依赖替换时阅读 [Mock 规则](mocking.md)。

## 每个行为切片

1. **red**：新增或修复行为先运行一个会捕获缺失行为或真实症状的测试。先修复 fixture、runner、权限或环境错误，这些错误不算 red。已有有效失败测试时复用；复现不了 bug 时先建立可重复的实际症状检查，不先猜测修复。
2. **green**：只实现当前行为所需内容，运行对应完整检查直到通过。不要一次批量写完全部测试再批量实现，也不预实现未来能力。结构重整由必要实现或获准的审查修复处理，不为了每轮重构扩大范围。
3. **record**：在运行产物中记录命令、关键失败/通过输出、先后顺序、证明的行为和范围。实现后的失败不能追认为实现前 red；记录 task 标识或名称供主 agent 核对进度。

保留既有行为的测试可以始终 green，说明它会捕获的回归，不故意弄坏 fixture 制造 red。一个测试围绕一个行为，可以有多个共同描述该行为的断言；优先覆盖批准的重要场景，不为数量拆碎断言。

文档、配置和包装任务不强制 red。使用机械验证或关键事实到权威来源的短映射；规范列表、版本和标识符需精确来源定位，普通描述不逐句建事实表。

## 验证与交接

开发中运行聚焦测试和适用静态检查。任务的必需检查必须完成；昂贵全套通常留到最终集成，由主 agent 按项目要求执行。修改使受影响证据失效时重跑，不以减少次数为由省略检查。

报告已实现、行为测试覆盖和承诺边界验证的区别。fake 只证明其覆盖的逻辑，不证明真实进程、网络或存储保证；必须的边界无法验证时报告阻塞，不宣称完成。

只修改分配的实现、测试和非契约交付物；获分配的 README、示例或配置任务可以按对应证据规则实施。Change 契约、批准状态及长期 Spec/Design/ADR 由主 agent 管理，不修改其他 lane 的文件。返回证据，由主 agent 更新权威任务状态。详细输出脱敏并保留到审查和交接结束。

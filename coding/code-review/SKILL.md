# Code Review

读取原始契约和当前代码，证据优先。默认一个 reviewer 分别报告两个轴，不合并或跨轴重排；本 skill 不启动其他 agent，也不修改项目文件。agent-workflow 中首次审查必须由独立 fresh-context reviewer 执行。

## 1. 确定审查对象

确认 repo/cwd、固定比较基准、当前候选树及完整变更清单。基准用可解析的固定 ref/SHA，不在审查中悄悄换到移动的分支 tip。主 agent 通常提供开工基准；不明确就询问，不假设 HEAD 的工作树差异包含全部交付。

检查从基准到候选的已提交变更、暂存及未暂存内容、未跟踪新增文件和删除文件。当前树净效果是判断对象；有 commit 或空 working-tree diff 不表示没有变更。无 Git 时使用明确的原始/候选快照或文件清单；没有可靠比较范围就报告阻塞。

读取 Change 及相关现行 Spec、Design、ADR和必要人工审批材料。读取适用项目指令、CODING_STANDARDS、CONTRIBUTING 等标准来源。摘要是索引，不替代原始要求。独立一般审查缺少契约时说明 Spec 轴无法判定；agent-workflow 不能因此跳过契约门禁并验收。

## 2. Spec 轴：契约符合性

- 核对所有重要行为、结构约束和非目标：遗漏、部分实现、错误实现、未经要求的行为或架构变化。
- 检查接口、错误、持久化、兼容性和外部交互，优先判断高风险保证。
- 审计测试：runner 实际执行，无遗漏等待、跳过关键检查、吞断言或自证预期值；能说明目标行为被破坏时哪个检查会失败。
- 核对 red 原因与时间顺序，fixture 或环境失败不是行为证据。保留行为核对声明的回归失败模式，不强制制造 red。
- 区分已实现、行为测试覆盖、承诺边界验证。unit fake 不能证明真实进程、网络或存储保证；必需证据缺失不能给通过结论。
- 检查要求、任务及验证是否自相矛盾。计划由主 agent 承担且尚未发生的长期文档同步，另列为最终验收前的收尾义务，不声称已经同步；writer 本轮应交付的文档缺失仍按实现缺陷报告。

每项契约发现给出原要求位置、相关代码、违反的行为或约束和具体证据。遇到规范空白不自行发明目标。

## 3. Standards 轴：项目标准

项目明确标准优先。检查有证据的命名、重复、职责分散、不必要抽象和耦合等问题；需要辅助判断时读取 [质量启发式](references/smells.md)。启发式只是判断，不是硬规定；工具已经强制检查的风格不重复审查。

每项发现引用标准或明确标为判断，说明实际影响。不用无契约、无复现、无代码支持的猜测阻塞交付。

## 4. 输出与复审

分别输出 `Spec` 和 `Standards`，每轴针对本轮候选交付明确通过、阻塞或无法判定；另列尚待主 agent 完成的收尾义务。每项发现带来源、代码位置、证据和处置类型：

- **契约阻塞**：冲突、重要空白或需要新产品/架构决定；主 agent 路由给用户。
- **实现缺陷**：违反确定要求、可达回归，或必需保证缺少承诺边界证据；writer 修复并验证。
- **可选建议**：不影响必需契约与验收，可以延后。

只要存在未解决的契约阻塞或实现缺陷，相应轴不能通过。通过附建议不能隐藏缺少必需证明；审查通过也不代替主 agent 的同步、最终机械检查或发布授权。

证据可先读运行产物，针对疑点复跑聚焦检查。默认不重复昂贵全套；检查会写项目生成文件时交 writer 或在隔离位置运行，保持只读与候选树稳定。

同一 reviewer 复审只读受影响 diff、原发现和新证据，确认连带范围；契约实质变化要重新阅读受影响原文。返回简短发现或插件管理的报告指针，不建立项目报告或第二份任务台账。

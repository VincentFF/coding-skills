# 质量启发式

仅在检查可维护性时按需参考。项目标准覆盖这些启发式；工具已经检查的模式不重复报告。具体影响可证实为契约缺陷时按缺陷处理，否则标为判断或可选建议。

| 现象 | 判断与可能处理 |
| --- | --- |
| Mysterious Name | 名字掩盖职责；按真实概念命名 |
| Duplicated Code | 多处重复同一逻辑形状；合并实际共有逻辑 |
| Feature Envy | 职责主要围绕另一个对象的数据；评估职责归属 |
| Data Clumps | 同一组值反复一起传递；评估是否构成有意义的类型 |
| Primitive Obsession | 基础类型掩盖真实领域概念；必要时定义小类型 |
| Repeated Switches | 多处重复相同分支映射；集中映射或选择合适结构 |
| Shotgun Surgery | 一个变化要求修改许多不相关位置；改善变化集中性 |
| Divergent Change | 同一模块因多种无关原因变化；评估职责拆分 |
| Speculative Generality | 为契约没有要求的未来能力添加接口或抽象；删减推测部分 |
| Message Chains | 调用者依赖深层导航；评估是否泄漏内部结构 |
| Middle Man | 包装层几乎只转发；确认是否仍承担真实约束 |
| Refused Bequest | 大量忽略或推翻继承契约；评估组合或重新建模 |

不要仅凭模式名称要求重构。给出实际代码位置和影响，修复范围不能超过批准交付。

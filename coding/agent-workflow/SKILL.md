# Agent Workflow

消费已批准的 Change，执行「worker → 独立 reviewer → 主 agent 收尾」。主 agent 保留用户沟通、需求决策、调度和验收权。仅讨论、编写或评估本 skill 不授权委派。

## 1. 开工门禁

用户明确请求通过 agent-workflow 执行、明确请求多 agent，或适用项目规则要求委派时，才启动 subagent。风险和复杂度本身不授权委派。只请求规划时停在 [change-planning](../change-planning/SKILL.md)，不启动实施。

读取 [文档契约](../change-planning/references/document-contract.md)，核实选择的 Change、批准依据、现行契约、依赖和必需验证。用户批准现有且一致的计划时不重复审批；未决的产品或架构决定先交用户解决。适用项目规则若要求另一套文档或工具流程，报告本入口不适用，不擅自绕过规则或静默切换。

获得委派授权后读取当前安装的 `pi-subagents` skill 及其所选分支要求的参考。缺少插件、必要规则、工具或验证条件时报告接入阻塞，不自动安装或换执行方式。

普通小修改可以不进入本工作流；一旦明确进入，不能因变更小而省略独立 reviewer。行为任务采用 TDD，非行为任务使用相应机械检查或事实核对。

## 2. 技能与分工预检

启动前读取 [执行交接](references/execution.md)。解析当前 skill 文件的真实位置，再解析同一技能集合中的 [tdd](../tdd/SKILL.md) 和 [code-review](../code-review/SKILL.md)。主 agent 确认路径可读，以绝对路径定向交接；不依赖子 agent 继承整个 skills catalog。子 agent 必须先读取所需规则和原始契约再工作，加载失败停止该 lane。

按 pi-subagents 的 topology preflight 记录单一紧耦合边界（single-seam）或多个独立可测试边界（multi-seam）。前者通常一个 worker；后者遵守插件的组件所有权、隔离、持久交接和后续集成所有者要求，不把所有独立结果交给一个宽泛 writer。

默认省略 scout；缺少范围证据且委派已授权时才使用有明确交付物的只读 scout。默认一个 reviewer 分别报告两个审查轴；只有独立风险角度需要不同审查时才拆分。

每个 cwd/worktree 同时只有一个写入者；在调度状态中记录所有权，不能因业务无依赖就并发修改共享文件。只启动达到前置交付门禁的任务；并行组件交接可恢复后才启动集成所有者。使用插件的异步机制和原生通知，不无故等待或重复建立项目台账。

## 3. 实施与进度

worker 读取 tdd，按批准任务逐个完成可验证行为切片；尽量保留同一 lane 的 worker 会话。详细证据进入运行产物，主 agent 根据证据和写入所有权更新权威任务进度。

writer 不修改需求、重要设计、ADR 或批准状态来迁就实现。遇到契约冲突或影响行为的契约空白，按文档契约暂停相关工作并交回主 agent；不改变契约的局部实现由 writer 决定。

在行为或集成边界留下短 checkpoint。续跑仅交接增量；更换 worker 时提供原始材料和 checkpoint，先验证当前树和所有权再恢复写入。

## 4. 独立审查与修复

候选结果稳定后，主 agent 按当前 writer 的交付范围筛查遗漏、已知失败和证据是否属于当前树；客观缺陷回到 writer，不为筛查提前反复跑昂贵全套。计划由主 agent 承担的长期文档同步留到收尾，不误报为 writer 遗漏，但验收前必须完成。

首次 reviewer 使用 fresh context、明确只读，读取 code-review、相关契约和完整 diff，独立核查 writer 的声明。主 agent 核实发现的有效性：契约问题交用户；实现缺陷回同一 writer；可选建议可延后。修复后复审受影响范围，尽量沿用同一 reviewer；同一争议两轮仍未解决时提交双方依据给用户。

修复不必重新批准，但改变契约必须先修订并获准。reviewer 的通过不代表文档已经同步，也不授予发布权限。

## 5. 主 agent 收尾与验收

writer 交出工作树后，主 agent 按文档契约同步长期文档并检查同步忠实性；无需从头重复完整代码审查。同步引入新语义时重新批准并复审，不能降低要求以消除缺陷。

主 agent 在集成、修复和同步后的最终树上独立运行项目必需机械检查。昂贵全套默认留到最终阶段；项目要求或修改导致结果失效时必须重跑，不限制「只能一次」。新增修改使受影响的验证与审查失效。

验收条件：必要交付、文档同步和适用人工审批完成；独立审查通过；没有未解决的契约阻塞或实现缺陷；承诺验证范围和最终树检查通过。必需验证无法完成时报告阻塞，不称为 accepted。commit、任务勾选或通过声明都不能代替门禁。

交付结果、精确验证及证明范围、可选建议和运行产物指针。状态回写遵守文档契约。现有耗时和成本数据可用于比较流程，不新建必填报告。

## 暂停与权限

同一失败经过两次真实修复仍无新证据，或调试没有可检验的新假设时，checkpoint 当前失败、尝试、文件和下一假设，由主 agent 决定继续或升级。健康的长检查不是超时猜测的理由。

委派、隔离或工具失败保留 run/worktree 和部分 diff；未经用户批准不静默转直接执行。暂停、修订或同步前明确交接写入权，不与 writer 并发编辑。

本地提交遵守适用策略；push、PR、发布及破坏性清理单独授权。保留证据到验收和交接结束，清理前确认无活跃所有者。旧 team-workflow 不参与本入口的自动路由。

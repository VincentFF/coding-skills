# 执行交接

## 技能路径

根据 Pi 提供的 skill 位置解析真实文件路径，使用真实父目录定位同一集合的兄弟 skills。不要相对项目 cwd 猜路径，也不要写死用户主目录。兄弟文件缺失时报告集合不完整；不自动安装上游仓库或改设置。

主 agent 预检计划、所需 skill 和条件参考可读；worker 至少收到 tdd 的绝对路径，reviewer 至少收到 code-review 的绝对路径。路径交接不依赖 skills catalog 的继承，也不需要统一的 Skill tool。

子 agent 首先读取角色规则和相关原始契约。失败时报告具体路径并停止，不能只回报「已加载」却按摘要继续。主 agent 可从运行记录核查读取行为；仅靠声明不是已经执行 TDD 或完成审查的证据。

## 新 worker

交接只包含当前任务需要的材料：

- 目标、repo/cwd、基准 ref 和当前候选位置、批准任务、必要模块或符号定位。
- 允许写入范围和操作、当前工作树所有者、非目标和停止条件。
- Change 及相关现行契约、重要人工审批材料和必须直接阅读的原文位置。
- tdd 绝对路径、批准的测试接口、验收条件、对应检查及最终集成义务。
- 文档或配置任务的关键事实到权威来源指针，仅列影响正确性的事实。
- 期望报告与运行产物位置；返回状态和证据，由主 agent 更新权威台账。

上下文指针用于索引，不替代原文。局部实现可以自行决定，影响契约的空白和冲突交主 agent。未经授权不再派子 agent。

## reviewer

交接 code-review 的绝对路径、相关原始契约、项目标准来源、固定基准、当前候选树、完整变更文件清单和读取方法，包括已提交内容及未跟踪新增文件。

附 worker 证据路径作为待核实声明、最高风险位置和本轮审查范围。首次使用 fresh context，禁止修改项目文件；正常回复或插件管理的产物可返回发现，不要求新建项目报告。

审查期间保持候选源树稳定。会改生成文件的检查交给 writer 或隔离执行，不能让只读 reviewer 变成并发写入者。

## 续跑与恢复

同一 worker/reviewer 只接收新任务或发现、变化文件、新证据和下一检查，不重复完整初始交接。

checkpoint 记录当前 repo/worktree/ref、完成和未完成任务、命令结果、未决事项、证据路径及下一行动。新 worker 接管时用首次交接加 checkpoint，独立检查当前树后才写入。

记录任务交付与工作树所有权使用插件运行状态或 lane board；不要新建第二份项目任务账。证据至少保留到审查、验收和必要恢复结束，日志中敏感值脱敏，不把完整输出复制进 Change。

# 项目工作流

- 仅讨论时分析问题，不写文件或启动实施。生成规划文档、批准契约和授权执行是不同动作，不能相互推断。
- 用户请求将共识整理成契约时，先读取 `change-planning/SKILL.md`。用户明确选择本工作流执行批准的 Change 时，先读取 `agent-workflow/SKILL.md`；普通小修改不强制启动团队流程。
- 工作流内，行为任务采用 TDD，候选实现必须经过独立 reviewer。主 agent 负责最终审核、长期 Spec/Design/ADR 同步和最终代码树验证，不能只凭任务勾选或 commit 宣称完成。
- 委派需要用户明确请求或适用项目指令授权；启用本提示、任务复杂或风险高，本身不授权启动 subagent。发布、push、PR 和破坏性操作另需相应授权。
- 项目指令提供技能集合根目录，以及现行 Spec、Design、ADR、Change 和必要人工审批材料的位置。未提供时只读定位已有安装和项目约定；读取前解析真实路径。必需 skill 不可读取时报告接入阻塞，不凭名称或摘要继续。
- 项目既有规范和审批要求继续生效。读取本次所需的原始契约与对应 skill，不默认加载整个文档库。契约冲突、重要空白或未经批准的范围变化先交用户决定，不修改要求来迁就实现。
